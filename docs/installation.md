# Installation

## Requirements

| Component | Version | Notes |
| --- | --- | --- |
| Node.js | 20.9 or later | 22 LTS is what CI uses. |
| npm | 10 or later | Ships with Node. |
| PostgreSQL | 14 or later | 16 is what CI and Docker Compose use. |
| Python | 3.11 or later | Only for the optional prediction service. |
| Docker | optional | Gives you PostgreSQL and the prediction service without installing them. |

The application creates no database extension beyond `pgcrypto`, which the
first migration enables for `gen_random_uuid()`.

## Local setup without Docker

```bash
git clone https://github.com/MaatlaHealth/Kea.git
cd Kea
npm install
```

Create a database and a user:

```sql
create database kea;
create user kea with password 'choose-something-local';
grant all privileges on database kea to kea;
```

Copy the environment template and fill in `DATABASE_URL`:

```bash
cp .env.example .env.local
```

For a local PostgreSQL that is not using TLS, set `DATABASE_SSL=disable`.

Apply the migrations and record the message templates:

```bash
npm run db:migrate
npm run seed:reference
```

Create your first administrator. The password is printed once and stored
nowhere else:

```bash
KEA_ADMIN_EMAIL=you@example.org \
KEA_ADMIN_NAME="Your Name" \
KEA_ADMIN_ORG="Your Health Service" \
npm run admin:create
```

Start the development server:

```bash
npm run dev
```

Open <http://localhost:3000>. Sign in at `/sign-in`. On first sign in you will
have an organisation and no facilities, so follow the checklist on
`/app/admin`: add facilities, configure referral pathways, invite staff, then
agree the escalation policy.

## Local setup with Docker

```bash
docker compose up --build
docker compose exec web npm run db:migrate
docker compose exec web npm run seed:reference
docker compose exec web npm run seed:demo
```

The compose file starts PostgreSQL, the prediction service and the web
application. The credentials in it are local development values and must not
be reused anywhere else.

To use the prediction service from the application, set
`PREDICTION_ENABLED=true` in the `web` service environment and restart it.

## The demonstration environment

```bash
npm run seed:demo
```

This creates a fictional organisation, four fictional facilities, seven
fictional staff accounts and eight synthetic patients, then drives real
referrals through the real workflow service. The password for every
demonstration account is printed once, or taken from `KEA_DEMO_PASSWORD`.

The organisation is marked as a demonstration environment and every patient
row is marked synthetic, which is what makes the interface label them as
fictional. The seed refuses to run against an organisation that is not marked
as a demonstration environment.

See [demonstration.md](demonstration.md) for a walkthrough.

## The prediction service

It is optional. The product works fully without it.

```bash
cd services/prediction
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

python -m kea_prediction.train --rows 8000
python -m kea_prediction.evaluate --rows 2000
pytest -q

uvicorn kea_prediction.app:app --port 8000
```

Then in `.env.local`:

```
PREDICTION_ENABLED=true
PREDICTION_SERVICE_URL=http://localhost:8000
```

The model is trained on synthetic data generated by this repository. It is
experimental and is not validated for patient care. See
[model-card.md](model-card.md).

## Messaging

Messaging is off until you configure it. While it is off, messages are still
created and queued so nothing is lost, and none are sent. A queued message is
never reported as delivered.

To turn it on you need a Twilio account, a sender, and a publicly reachable
callback URL:

```
MESSAGING_ENABLED=true
TWILIO_ACCOUNT_SID=...
TWILIO_AUTH_TOKEN=...
TWILIO_MESSAGING_SERVICE_SID=...     # or TWILIO_SMS_FROM
TWILIO_WHATSAPP_FROM=+27...          # for WhatsApp
TWILIO_WEBHOOK_URL=https://your-host/api/webhooks/twilio
```

In the Twilio console, point the messaging status callback at
`https://your-host/api/webhooks/twilio/status` and the inbound webhook at
`https://your-host/api/webhooks/twilio/inbound`. The URL must match
`TWILIO_WEBHOOK_URL` exactly, because it is part of the signature that is
verified on every request.

For local development, expose port 3000 with a tunnel and set
`TWILIO_WEBHOOK_URL` to the tunnel address.

WhatsApp requires each template to be approved by the provider before it can
be sent outside a customer initiated session window. Recording a template in
Kea does not approve it.

## Scheduled jobs

Acknowledgement deadlines, missed appointment detection, reminders and message
dispatch run from one endpoint:

```bash
JOB_RUNNER_TOKEN=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))")
curl -X POST -H "Authorization: Bearer $JOB_RUNNER_TOKEN" http://localhost:3000/api/jobs/run
```

Run it every 15 minutes in a deployed environment. See
[deployment.md](deployment.md).

## Troubleshooting

**`Invalid environment configuration: DATABASE_URL: Required`**
`.env.local` is missing or does not define `DATABASE_URL`. The build itself
does not need a database, but running the app does.

**`self signed certificate` or TLS errors on connect**
Set `DATABASE_SSL=disable` for a local instance, or `require` for a managed
one that presents a valid certificate.

**Migrations fail with `permission denied to create extension "pgcrypto"`**
Ask your database administrator to run
`create extension if not exists pgcrypto;` once as a superuser, then re-run
the migration.

**Integration tests are skipped**
They skip when no database is reachable at `DATABASE_URL`. Start PostgreSQL
and run `npm run db:migrate`.

**Playwright tests are skipped**
They skip when `KEA_DEMO_PASSWORD` is not set. Seed the demonstration data
with that variable set, then run the suite with the same value.

**Fonts fail during `npm run build` on a machine with no network**
The build fetches the two Google fonts it inlines. Build on a machine with
network access, or vendor the font files and switch to `next/font/local`.
