# Kea referral non-attendance service

> **Experimental.** Trained on synthetic data generated by this repository.
> Not validated for patient care. See [../../docs/model-card.md](../../docs/model-card.md).

An optional service that estimates how likely a booked referral appointment is
to be missed, from referral workflow features only. The Kea application works
fully without it: when it is off, coordinators prioritise using the
operational rules built into the product.

The service holds no patient data. It receives a feature vector, returns a
score, and stores nothing.

## Running it

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

python -m kea_prediction.train --rows 8000
python -m kea_prediction.evaluate --rows 2000
pytest -q

uvicorn kea_prediction.app:app --port 8000
```

Or with Docker, which trains the baseline during the build so the image ships
with a usable artefact:

```bash
docker build -t kea-prediction .
docker run -p 8000:8000 kea-prediction
```

## Connecting it to the application

```
PREDICTION_ENABLED=true
PREDICTION_SERVICE_URL=http://localhost:8000
PREDICTION_SERVICE_TOKEN=            # optional shared secret
```

With no token configured the service is open, which is only appropriate on a
private network or a local machine.

## Endpoints

| Route | Purpose |
| --- | --- |
| `GET /health` | Model name, version, feature set version, and whether it is validated |
| `GET /features` | The feature contract, including the characteristics excluded by design |
| `POST /predict` | Score a feature vector |

## Modules

| File | Purpose |
| --- | --- |
| `features.py` | Feature names, descriptions, defaults and banding. Must match `src/lib/prediction/features.ts`. |
| `synthetic.py` | The data generator, with its assumptions stated in the docstring. |
| `train.py` | Trains the logistic baseline and a gradient boosted comparison, writes the artefact and its metadata. |
| `evaluate.py` | Discrimination, calibration and a confusion matrix on freshly generated data with a different seed. |
| `model.py` | Loads the artefact and produces an explainable score. |
| `app.py` | The HTTP interface. |

## Versioning

The feature set version is sent with every request and the application rejects
a mismatch with `409`, so the two sides cannot silently drift apart. Changing
the feature list, their order or how any of them is derived requires a new
version string in both places.

## What this model must not be used for

It does not diagnose, does not predict a clinical outcome, does not assign
clinical urgency and never changes what a patient is told. See the model card.
